[1] Introduction

We’re introducing Nex Coder 3.8 Preview — Neptune, the depth-oriented profile of the AA4 / Zorix4 generation.

Neptune is designed for repository-scale software engineering, adaptive planning, tool execution, and verification-heavy workflows. It is intended for work where understanding the whole system matters as much as producing the next block of code.

The current preview profile publishes a 2 million token context window. Its parameter count remains undisclosed, and Zorix currently describes the architecture as Closed / AA4.

Neptune is currently a preview model. Availability can differ while the preview is being rolled out.

[3] Repository work

Repository-scale engineering

Neptune is built around the idea that difficult software work is rarely isolated to one file, one function, or one turn.

01
Work across the repository
Use long context to reason across code, configuration, documentation, dependencies, and related implementation details rather than treating files as isolated fragments.
02
Plan before changing
Neptune’s preview profile is oriented toward adaptive planning: understanding the task, identifying affected surfaces, and updating the plan as evidence changes.
03
Use tools as part of the loop
Tool execution is treated as part of the engineering process—not a final step after reasoning is complete.
04
Verify the result
Neptune is designed for verification-heavy workflows where tests, command output, diffs, and resulting system behavior feed back into the next decision.
